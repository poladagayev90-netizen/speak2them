# Onboarding, WhatsApp number, intro call, first run

Moved out of CLAUDE.md on 2026-10-15 so it is read only when a task touches this area. Facts are kept as written; keep this file current when the code changes.

- **Onboarding** (`src/pages/Onboarding.jsx`, one question per slide): home `/` redirects to `/onboarding` while `users.onboardingVersion < ONBOARDING_VERSION` (`src/utils/onboarding.js`); bump the constant to re-ask everyone. Sensitive answers (age band, country, confirmed IANA `timeZone`, weekly `availability` in the learner's OWN time, `weeklyTarget`) live in `onboarding/{uid}` (owner + admin only) — never on the world-readable `users` doc. Availability ≠ commitment: the wizard caps `weeklyTarget` at the number of free days. Convert to Baku only at display time via `src/utils/timezone.js`. Admin reads it in Admin → Applicants (per-person local time, common free time, "who is free when" heatmap).
- **WhatsApp number + week profile + «What happened?»** (Faza 3, 2026-10-07): `ONBOARDING_VERSION = 3` — the wizard has a `phone` step after the charter; version-2 learners are sent straight to it (one step, Save). `onboarding/{uid}.whatsapp` is E.164 (`normalizeWhatsApp` in `src/utils/onboarding.js`, the same regex in rules), MANDATORY, team-only — never on `users`; Admin → Students/Applicants open it with `whatsAppLink`. The grid paints **Free** (`availability`) / **Maybe** (`maybeAvailability`) / **Never** (`busyAvailability`), one state per cell (`src/utils/weekProfile.js`, `PaintModes` in TimeGrid); saving the grid stamps `weekProfileAt` (server time), and Today's `WeekProfileCard` asks learners with `callCount > 0` who have none. Planner (`weeklyPlanner.slotOptions`): Maybe = candidate with −1 per side, Never = refused even inside the week's picked hours (`autoRoster.weekAvailability` subtracts it; `weekMaybe` drops maybe when hours were picked). After the learner's own `no_show` / `late_cancel` / `cancelled` (attendance) or a time-change request, `MissReasonCard` / BookingRow ask once: `missReasons/{eventId}_{uid}` (owner create-only, admin read; shown on Admin → Attendance); «wrong time» → −1.5 on that weekday + Baku hour for 8 weeks (`wrongTimes` in `loadPlannerInputs`) and a one-tap «Mark Tue 20:00 as Never». Decline reasons stay in `matchOfferNotes`.
- **Intro call** (`/intro`, `src/utils/intro.js`): **NOT required since 2026-09-28** — `INTRO_REQUIRED = false`. After onboarding `/intro` only points the learner to the team's WhatsApp (name + level prefilled); any call and its time are arranged there by hand, and the in-app slot picker is gone. Nothing is locked — calls are free — but **WhatsApp comes first for newcomers**: accounts created from 2026-09-28 (`mustWriteWhatsApp`) are sent from home to `/intro`, which has no way on (and no bottom nav) until they tap the WhatsApp button once; the tap writes client-owned `users.introWhatsAppAt`. A tap is not proof a message was sent. Every lock goes through `introLocks(user)`; flipping the flag back makes random search, the slot board (Live) and direct calls wait for `users.introDoneAt` again, which is rules-protected and set only by `adminMarkIntro`. `needsIntro()` exempts anyone already practising (`callCount > 0`), anyone with a teacher, cohort members, teachers and the admin. `teamSlots` are admin-written and world-readable, so they hold NO learner identity; bookings live in `introBookings/{uid}`. Reminders ride on `practiceSlotTick`. Admin → Intros opens times and records outcomes.

- **UI copy is English.** The whole interface was moved to English and `i18next` removed (2026-08-21). Two exceptions: the analysis report, which stays in the learner L1 (`users.preferredLanguage`, az/tr) — see `src/utils/feedbackLanguage.js`. And the **first run** (2026-10-14): Register → Onboarding → `/intro` → Today's first tour speak the learner's pick of **az / tr / ru / en** (`src/utils/firstRunLang.js`, words in `src/data/firstRunCopy.js` — a test fails when a language misses a key, so new first-run copy is written four times; saved VALUES stay English). The pick is `users.guideLanguage`; az/tr also set `preferredLanguage`. On its first day (`isFirstDay`) Today opens no streak / topic pop-up, only the 6-stop tour (`tourDone_home_v4`, 2026-10-17: next practice · topic · AInur tab · Lab tab · the Leaderboard row on Today · Partners tab — all on Today, the tour never changes page). `InstallGate`'s own words follow the first-run language too (`gate.*` keys); its per-browser steps (`utils/installGuide.js`) stay English, and Android phones get one Google Play button instead of the home-screen steps. `public/index.html` is `lang="en"`; do not set it back to `az` without also reverting the copy, or `text-transform: uppercase` breaks Azerbaijani text.

- **Editing one answer** (2026-10-18): Plan / Today open the wizard with `location.state = { jumpTo, returnTo }`. In that edit mode the back arrow AND Android back (`useBackButton`) leave to `returnTo` (or history back), dropping the unsaved draft — never to the previous step. A pencil on the review («Review all my answers») edits that one answer and Continue returns to the review (`fromReview`), not on through the later steps; only fewer free days than the target passes the target step first.
