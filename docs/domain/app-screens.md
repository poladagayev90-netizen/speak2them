- **Online now** (2026-10-06, TEMPORARY — remove once the weekly plan carries everyone): `onlineNow` (us-central1) returns up to 12 learners seen in the last 150 s, filtered SERVER-side by the hard pairing rules (block / avoid either way, minor↔adult — the age band is private), never teachers/admin, never anyone with `users.showOnline === false` (Profile toggle). **Freshness** (2026-11-10, Polad: «iki onlayn tərəf bir-birini gec görür»): the server caches only the presence query for 5 s (`ONLINE_NOW_PRESENCE_MS`, newest `lastSeen` first, limit 60) and each caller's own relations (age band, blocks, avoids) for 60 s; the client asks every 15 s while visible and again on visibility / Android `resume`; App.js marks the user offline on Android `pause` and online on `resume` (not during a call). Rate limit 480/hour. Before this, a 20 s per-instance roster cache + a 30 s poll made an arrival take a median 23 s and up to ~50 s to appear. The strip (`OnlineNow.jsx`, `useOnlineNow`) sits on Partners only (removed from Today 2026-10-06); since 2026-10-07 the same list marks partner rows «Online» / «In a call» (and sorts them up), the strip shows only non-partners and stays as one line «Nobody else is online right now»; Call = `navigate('/chat/<uid>', {state:{autoCall:true}})`, so `canPair({direct:true})` still decides. Switch: Admin → Matching «Online now list» = `appConfig/features.onlineNow` (missing = on).

- **App updates** (2026-10-07, `src/utils/appUpdate.js` + `components/UpdateBanner.jsx`): web/PWA compares the running `main.*.js` with `/asset-manifest.json` (on load, every 30 min, on return to the screen); a newer build shows «A new version… · Refresh» and is applied by itself on return to the screen unless a call / chat / wizard / admin or teacher desk is open — the old instant `location.reload()` on a new service worker is gone (the SW `skipWaiting`s and fetches network-first, so a reload is the whole update).
