# Individual lessons, /lessons, topic cycle, session schedule

Moved out of CLAUDE.md on 2026-10-15 so it is read only when a task touches this area. Facts are kept as written; keep this file current when the code changes.

- **Individual lessons** (2026-10-02; replaced the group-class model, which had no real classes): a teacher's linked student (`users.teacherId`, teacher code) gets an enrolment `tutorStudents/{uid}` (level A2/B1, `packageSize`, platform Preply/Meet, link) and their OWN lessons `tutorLessons/{id}`, each stored with its own `at` — moved, cancelled (`cancelledBy`), restored or removed one by one. The admin adds a learner without the code (teacher dashboard → "Add a student" → their page → Start lessons): `teacherLesson` "start" by the admin links an unlinked learner to the admin (`users.teacherId`, roster row, counters — `addToTeacherRosterTx`, shared with `claimTeacherCode`); other teachers still need the code or an accepted invite (the learner's consent). Today shows lessons ONLY as rows in «Coming up» («Lesson 2 · its topic», the next lesson always keeps a row) — the 48 h picture card was removed 2026-10-12 (Polad: two picture cards next to the daily topic looked crowded); a lesson's topic is fixed when planned, the daily one keeps moving. Every write goes through `teacherLesson` (the student's teacher or the admin; `functions/tutorLessons.js` pure + tested: weekly pattern → dates in Baku time, next-topic suggestion, held numbering). Only HELD lessons use the package; held lessons are numbered by date (`n` = the story episode). Starting lessons / a bigger package extends `freeAccessUntil` by 90 days — only for the admin or a `teacherVerified` teacher, because `role: teacher` is self-chosen at sign-up. Marking held builds `homework/{lessonId}` (topic words + dictation + a personal half from the learner's analyses since the previous held lesson, `functions/homeworkBuilder.js`); undo hides, never deletes. The learner's planned lessons sit in Today's "Coming up" and the Plan tab's schedule next to booked practices (`useMyLessons`, `lessonItems`/`mergeSchedule`, `LessonRow` — a book icon and a purple bar; tap → materials), `LessonsCard` keeps package progress + homework, and the learner prepares on `/class/:lessonId` (the topic sheet, `DailyTopicModal topicIndex`); the teacher sees `StudentLessons` on the student page and "This week" on the dashboard, and — like the admin — their OWN Today/Plan show the lessons they teach (`useTeachingLessons`, `teachingItems`: rows in Coming up / the Plan schedule with «Open» → `/class/:id`); Today hides «Set up your practice plan» for teachers and the admin. A teacher's `tutorLessons` query must include `teacherId == me` or the rules refuse it. `practiceSlotTick` pushes each planned lesson twice — `lesson_prepare` ~3 h before and `lesson_soon` 15 min before, both opening `/class/:id` (`tutorLessons.reminderDue`; the lesson's `reminded.{prepare,soon}` holds the start time it was sent for, so a moved lesson is reminded again; paused enrolments get nothing; index `tutorLessons (status, at)`). Before a lesson the teacher opens the student's brief (`teacherStudentBrief` → `classBrief.buildStudentBrief`: their mistakes and words since the last held lesson, that lesson's homework progress — counted, never guessed). `homeworkStepKeys` (`src/utils/tutorLessons.js`) is mirrored in `functions/classBrief.js` — change both. The Julian story (`functions/storyBible.js`, approved by Polad) is ONE shared episode per level: `storyChapters/{level}_{n}`, written by `teacherStory` (DeepSeek + Deepgram audio in Storage, agreeing with the level's earlier episodes; no lesson topic) and approved once — only by the admin or a `teacherVerified` teacher, since every student of the level reads it. Episode n is read BEFORE the student's n-th lesson on `/class/:lessonId` (listening reveals the last choice, reading ends on the dilemma the lesson debates); its recorded sentences become the homework dictation. Learners read approved episodes only if they have a `tutorStudents` doc. Import `cohort.css` before `story.css`, and `ui.css` before `plan.css`, or the CI build fails on CSS chunk order.
- **Lessons** (`/lessons`, `/lessons/:lessonId`): 17 short lessons in 4 modules (`src/data/lessons.js`) teaching HOW to practise — describing, keeping a call alive, Taboo, debate. Written because the median production call ran 40 s and two thirds opened no activity. **Nothing is locked**: `nextLesson()` (`src/utils/lessonMap.js`, pure + tested) only RECOMMENDS. Progress is the one client-written progress doc, `lessonProgress/{uid}` — safe only because nothing is granted by it; if a lesson ever unlocks anything, move the write to a Cloud Function. Lesson **ids are storage keys** — add, never rename. Phrase meanings (az/tr) live in the lesson data and are revealed on tap, like `KeywordChips`.
- **Topic cycle**: global monotonic tick in `appConfig/cycle`; `topicIndex = cycleTick % TOPIC_COUNT`. Progress is **not** stored per user — the client computes `currentCycleTick - startTick`. `functions/dailyQuestions.json` and `src/data/weeklyContent.js` must stay the same length.
- **Session schedule**: `src/utils/sessionSchedule.js` + `appConfig/session`. Times are **Baku (UTC+4, no DST)** so every client computes the same window. **One session only: 21:00** (the 16:00 afternoon session was removed — never re-add a daytime reminder). 21:00 is a **recommended hour shown every day**; `sessionDays` Mon/Wed/Fri + `bonusDays` Sun only mark the **main** days (crowd + topic-cycle advance), they never gate practice — any user can search for a partner at any time. Weekdays are **0=Sunday…6=Saturday — Sunday is 0, not 7**. Use `getUpcomingSessionWindow()` (countdown) / `getSessionWindow()` / `getNextSessionDay()` — don't hand-roll time math. The Firestore doc's `sessions` array **overrides** the code defaults, so a config change needs both.
