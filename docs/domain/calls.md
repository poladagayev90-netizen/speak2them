# Calls: topic, minutes, incoming / missed call, push payloads, in-call videos

Moved out of CLAUDE.md on 2026-10-15 so it is read only when a task touches this area. Facts are kept as written; keep this file current when the code changes.

- **Call minutes are authoritative from call timestamps**, never the client stopwatch. A call starts at `connectedAt` (written once when both are in the Agora channel) → `matchedAt` → `createdAt`. The client's `authoritativeDurationSec` is only a claim: the server credits `trustedCallSeconds` (functions/practiceStats.js) = min(claim, endedAt − start, 60 min), and the rules only accept `serverTimestamp()` for a call's clock fields. Call ids are per PAIR (`call_<a>_<b>`), so server code creating a call must overwrite the doc, never merge — a merge inherits the previous call's flags and duration.
- **Call topic** (2026-10-06): a call has ONE shared topic, `calls/{id}.callTopic` (`contentIndex`, `by`, `at`; missing = today's). The «Topic · Change» chip on the call screen opens `CallTopicPicker` (today, the coming days' topics with their date — `upcomingTopics` in `src/utils/topicQueue.js`, pure + tested, follows the session days the cycle advances on — then all topics); picking moves BOTH screens, the partner gets a one-line note, and the vocabulary sheet and every activity started afterwards pin that index. Today shows «Next topics» under the topic card (tap = that topic's sheet). A MISSING `calls` doc is readable by the two uids its id names — otherwise the call screen's listener died before the first call between a pair existed and the caller hung on «Calling…».
- **Incoming call on Android** (v29 / 1.19, 2026-10-07): the APK writes `caps: ['ring']` on its `fcmTokens` doc; the server then sends `incoming_call` to that token DATA-ONLY (`pushTokens.buildMessage` platform `android-ring`; old APKs keep the notification block). `CallMessagingService` (extends the push plugin's service, which the manifest removes) draws a CallStyle notification on channel `calls` — ringtone, `FLAG_INSISTENT`, 45 s, full-screen intent, Answer / Decline — only while the app is not on screen; taps open MainActivity (shows over the lock screen) with FCM-style extras → `nativePush` → `utils/callIntent.js` → `GlobalCallListener` accepts / rejects once the call doc arrives. Play Console needs the Full-screen intent declaration («calling app»).
- **Missed call**: `reconcileCallStats` sees `calling → ended` with no answer and pushes `missed_call` to the person called (claimed once in `slotRuns`); on web and Android it replaces the ringing notification (same tag). A decline goes through `rejected` and is not reported.
- **Push payloads differ by platform** (`functions/pushTokens.js`): web = data-only + `Urgency: high` (the SW displays it); Android = `notification` block + `priority: high`. Adding a notification block to web causes duplicate notifications.
- **Guess It scoring** (fixed 2026-11-06, `src/utils/guessGame.js` + `CallGuessStage`): each phone opens the round on ITS clock, so drift let one player bank a point at the first reveal while the other still typed a closer number — both scored and the winner flipped. Now each answer carries `guessStage.answeredAt.<uid>` (serverTimestamp) beside `guessStage.startedAt`; `countedGuess` drops an answer stamped later than 45 s + 3 s grace (a missing stamp — old app, or my write in flight — is trusted), and the point is written only when the result is final (both answers + stamps in, or 3 s after the local deadline). `parseGuess` reads `1.400` / `1.400.000` as thousands (AZ/TR/RU grouping); `1.5`, `1.4k` stay decimals.
- **Describe-video clips in the Android app** (2026-10-13): `licensed: true` (Pexels / CC0) OR `playOk: true` (animals / nobody recognisable — Polad: clips showing a recognisable person, children and possibly local people above all, stay web-only), six per topic (`appVideosForTopic`); `scripts/strip-native-videos.js` keeps only their files in the APK/AAB and fails the build if it finds none. A new clip is web-only until it gets one of the two flags. **Sound** (`sound: true`) plays only in ClipViewer on web; calls and AInur are always muted. **In-call Video runs everywhere**: `videoStage.deck` = `app` once either side is native, `full` between two web users (`callVideosForTopic`); clients write `calls.clientCaps.<uid> = ['licensedVideo']` and the button is hidden for a partner on an older APK without it.
- **Warm-up call** (2026-11-06, Polad approved Gemini Live): a newcomer's ONE spoken chat with AInur before their first real partner — `/warmup` (`src/pages/WarmupCall.jsx`), offered by `WarmupCard` on Today. **Product rule: SpeakLab is practice with REAL people; the warm-up is a bridge, never "the AI practice".** It says so in four places — the Today card, the intro screen, the in-call badge «Warm-up · next: a real partner», and AInur's own goodbye (her prompt) — and the closing screen's only ways on are Partners (`/chats`, Online now) and the week (`/plan`). No defensive copy. Who gets it (`functions/warmupCall.js` `warmupEligibility`, mirrored by `src/utils/warmupCall.js` `showWarmupCard`): never a teacher, never anyone with `callCount > 0`, one per learner — a second try only if the first ended under 60 s or with under 3 learner words (`MAX_ATTEMPTS = 2`). Copy is first-run copy (`warm.*` keys, az/tr/ru/en); AInur speaks English, and one short sentence in the learner's L1 when they fall into it.
  - **How it runs:** `warmupCallStart` (us-central1) mints a ONE-USE Gemini ephemeral token (`POST v1beta/auth_tokens`, `liveConnectConstraints`) with model, voice and the whole system prompt locked in; its `expireTime` is the hard length cap (240 s + connect window + grace). The browser connects straight to `BidiGenerateContentConstrained` (`src/utils/geminiLive.js`, PCM 16 kHz up / 24 kHz down via `src/utils/livePcm.js`). **Half-duplex on purpose:** the mic is not sent while AInur plays (+350 ms) — without it a phone on speaker feeds her voice back, she interrupts herself and her words land in the learner's transcript. Stage cues `[start]` / `[wrap-up]` go as `clientContent` text; the client sends `[wrap-up]` at 170 s and hangs up after her goodbye, or at 240 s. VAD `silenceDurationMs` 1200 + low end-sensitivity (learners pause mid-sentence — same lesson as `SILENCE_STOP_MS`).
  - `warmupCallEnd` computes the length from the SERVER's start time (client stopwatch never trusted), stores the transcript lines in `warmupCalls/{uid}` (learner reads own, server writes only), and picks one thing the learner said well with gemini-3.8-flash (`validBest` requires the quote to be the learner's own words; fallback = their longest line).
  - **Cost:** gemini-3.8-live $0.005/min in + $0.018/min out (read 2026-11-06), but Live re-bills the whole context each turn → a typical call ~$0.04, ceiling ~$0.20. Budget: every started call reserves `RESERVE_USD` 0.15 in `agentUsage/{month}.warmupUsd`; `appConfig/warmupCall` `{ enabled (missing = on), monthlyUsd (default 15), model, voice }`; over budget → the page goes straight to partners. Rate limits: `warmupStart` 4/day, `warmupEnd` 6/day per user. `reportedTokens` (client-seen usage) is stored to check the reserve against reality.
