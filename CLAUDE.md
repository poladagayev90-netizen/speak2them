# SpeakLab (speak2them)

English speaking-practice app: React PWA + Firebase + Agora voice calls, wrapped as an Android APK with Capacitor. Business model: **a free month, then monthly packages of planned practice** (see Practice packages) — no popups or upsell screens; the packages page is reached only from Profile.

## Stack
- **Frontend**: React 19, CRA (`react-scripts`), PWA. `src/pages`, `src/components`, `src/utils`, `src/hooks`.
- **Backend**: Firebase Cloud Functions **v2** — almost everything in `functions/index.js` (~7,500 lines) plus small modules beside it (`pushTokens.js`, `practiceStats.js`, …). Native `fetch`, no AI SDKs.
- **Data**: Firestore (`firestore.rules` + `firestore.indexes.json`).
- **Voice**: Agora RTC. **AI**: Groq (Whisper STT + Llama), Deepgram (TTS), DeepSeek/Gemini (analysis).
- **Mobile**: Capacitor 8, package `com.speaklab.app`.

## ⚠️ Deploy safety — read before committing
- **`git push origin main` auto-deploys the web app to production** (Vercel). There is no staging. Treat a push as shipping to real users.
- **Default to showing the diff and asking before pushing**, unless the user explicitly says to deploy.
- Cloud Functions deploy separately and manually: `npx firebase-tools deploy --only functions --project speak2them-64f2b`.
- Functions live in **two regions**: **all six** Firestore triggers (`initTrialForNewUser`, `notifySearchingUser`, `reconcileCallStats`, `notifyChatMessage`, `notifyAdminOnboarding`, `syncUpcomingCall`) run in `europe-west4`; everything else `us-central1`.
- `CI=true` makes ESLint warnings fatal — a warning breaks the deploy. Verify with `CI=true npx react-scripts build` (Bash tool; PowerShell mangles the env prefix).
- Backend-only changes (`functions/`) do **not** require rebuilding the Android AAB.

## Core domain rules — don't break these
- **Onboarding** (`src/pages/Onboarding.jsx`, one question per slide): home `/` redirects to `/onboarding` while `users.onboardingVersion < ONBOARDING_VERSION` (`src/utils/onboarding.js`); bump the constant to re-ask everyone. Sensitive answers (age band, country, confirmed IANA `timeZone`, weekly `availability` in the learner's OWN time, `weeklyTarget`) live in `onboarding/{uid}` (owner + admin only) — never on the world-readable `users` doc. Availability ≠ commitment: the wizard caps `weeklyTarget` at the number of free days. Convert to Baku only at display time via `src/utils/timezone.js`. Admin reads it in Admin → Applicants (per-person local time, common free time, "who is free when" heatmap).
- **Practice packages** (2026-10-04, `functions/packages.js` pure + tested, display mirror `src/utils/packages.js`): what is sold is PLANNED practice a month — 8 / 12 / 16 / 20 for 6 / 8 / 10 / 12 AZN (`appConfig/billing.packages`), not minutes. New learners get a **free month: 2 planned practices a week for 4 weeks** from sign-up — or from the day the switch was first turned on (`enabledAt`), whichever is later. The balance is NEVER stored: `accessState` derives it from the learner's `bookings` (used = attended / no_show / their own late cancel; reserved = confirmed; returned = partner_no_show, "arrived", in-time cancel, cancelled by someone else — the platform's failures cost nothing). Renewing early moves everything left over; after the end only the returned ones, max `carryMax` 4. Unlimited = admin, `isPremium` ("Make Pro"), cohort, `freeAccessUntil`, a plan other than trial/free — rules-protected fields only, NEVER the client-writable `mode`. Only planned practice is limited — `joinSlotTx` (403 `no-practices-left`), `bookPairTx` for `admin_offer` (409 `student-{a,b}-no-practices`; the one who ran out is told, the other only "did not work out"), `createPlanOfferTx`, `loadPlannerInputs`; teacher pairs, direct calls with friends and AInur are never limited, and the old 60-day lock on the Agora token and the app-wide `TrialExpiredGate` are GONE. **`appConfig/billing.enforce` is OFF by default** (Admin → Students → "Packages ON/OFF", `adminAccess setEnforce`): off = counted and shown, nobody refused. `access/{uid}` (server-only) holds the package + history, written by `adminAccess grant/revoke` (later a Google Play receipt check must call the same `grantPackage` — digital goods on Play go through Play Billing). The app reads `planStatus/{uid}.access` (refreshed by `syncUpcomingCall` on every booking change and by `adminAccess`). `/packages` (sea-creature cards, WhatsApp "Get it" for now) is NEVER opened by the app: Profile shows "Your plan" only once there is a package or the free month is over with the switch on; Today/Plan add one quiet line only when the switch is on and nothing is left. The 100-minute counter (`availableTrialMinutes`, `consumeTrialMinutes`) still runs but means nothing.
- **Intro call** (`/intro`, `src/utils/intro.js`): **NOT required since 2026-09-28** — `INTRO_REQUIRED = false`. After onboarding `/intro` only points the learner to the team's WhatsApp (name + level prefilled); any call and its time are arranged there by hand, and the in-app slot picker is gone. Nothing is locked — calls are free — but **WhatsApp comes first for newcomers**: accounts created from 2026-09-28 (`mustWriteWhatsApp`) are sent from home to `/intro`, which has no way on (and no bottom nav) until they tap the WhatsApp button once; the tap writes client-owned `users.introWhatsAppAt`. A tap is not proof a message was sent. Every lock goes through `introLocks(user)`; flipping the flag back makes random search, the slot board (Live) and direct calls wait for `users.introDoneAt` again, which is rules-protected and set only by `adminMarkIntro`. `needsIntro()` exempts anyone already practising (`callCount > 0`), anyone with a teacher, cohort members, teachers and the admin. `teamSlots` are admin-written and world-readable, so they hold NO learner identity; bookings live in `introBookings/{uid}`. Reminders ride on `practiceSlotTick`. Admin → Intros opens times and records outcomes.
- **Who may be paired** (`pairVerdict` in functions/index.js) — used by EVERY pairing path (slot board `joinSlotTx`, rematch in `leavePracticeSlot`, `bookPairTx`, `adminProposeMatch`, random search via `canPair`). Hard: a block either way, `users/{uid}/avoid/{peer}` ("don't pair me again") either way, minor (onboarding `ageBand: under18`) with adult, and — automatic pairing only — `partnerLevel: 'close'` with a CEFR gap > 1. Soft: a partner met in the last 7 days goes last. Random search asks `canPair` before `commitMatch` because the lists are private; the API never says which rule refused. Post-call behaviour tags go to admin-only `partnerFeedback`.
- **Attendance** (`attendance/{id}`, server-written only): `attended` (any held call >= 2 min, from `recordCallPractice`), `no_show` / `partner_no_show` / `unmatched` (decided at slot-block CLOSE, so late arrivals count), `late_cancel` (< 2 h before) / `cancelled` (from `leavePracticeSlot`, confirmed bookings only). `partner_no_show` and `unmatched` are the PLATFORM failing the learner — shown to the admin separately, never counted against them. Home "Your week" = onboarding `weeklyTarget` vs attended; Admin → Attendance flags learners for a conversation.
- **Bookings** (`bookings/{slotId}_{lo}_{hi}`, server-only, `functions/bookings.js`): one record per booked pair per 2-hour block, written in the SAME transaction as the `practiceSlots` member docs (which stay — the tick, `arrivedAt` and old APKs read them). A learner may hold several bookings. The **weekly plan** keeps them to one per Baku day (`sameDayBookingsTx`: weekly-plan offers, the planner, respondSlotChange); a **teacher or the admin pairing by hand may add a second call the same day** (`bookPairTx` `oneADay:false`) — only a partner in the SAME 2-hour block refuses (accepted admin offers never replace one: `replaceInBlock:false`; a teacher re-pair in the same block does). `users.upcomingCall` is **derived** — never write it directly: `syncUpcomingCall` sets it to the nearest confirmed booking. The pair's `calls/{id}` doc is written only when the start is ≤ 30 min away (`planCallDocTx`), otherwise by `practiceSlotTick` at T−15; a doc written days ahead made old APKs join an empty room on opening the chat. Offers/teacher pairs reach `BOOKING_HORIZON_DAYS` (9); the board stays at 5. This is Phase 2 of the scheduled-practice plan.
- **Today / Plan / Partners** (Phase 4): the Live tab and its files are gone (`/live` → `/plan`; random search has no client any more, `canPair` stays for old APKs); nav = Today · Plan · Partners · AInur · Profile (Leaderboard inside Profile). Today answers "what now?" with ONE card from `planHeadline()` (`src/utils/planState.js`, pure + tested: setup / next / answer / paused / done / no_match / waiting — never a promise of a partner), then Get ready, then This week. Plan (`src/pages/Plan.jsx`) is the whole week: proposals ("Confirm all"), bookings (join / message / change time / cancel), free times + target (edited through the onboarding wizard with `state.jumpTo`/`returnTo`), and the `planPaused` switch. Partners = the old Chats page + a call button per person. Onboarding v2 adds the **charter** step (`charterVersion`, `charterAcceptedAt` = server time); v1 learners are brought straight back to it with their answers kept. Data: `useMyPlan` (bookings, offers, planStatus, onboarding, attendance).
- **Weekly plan** (Phase 3; `functions/weeklyPlanner.js` pure + tested, `functions/availability.js` = server copy of `src/utils/timezone.js` — keep them in step): every Sunday 12:00 Baku `practiceSlotTick` drafts `weeklyPlans/{monday}` (admin-only) from onboarding availability (≥ 30 free minutes from a block's start) + `weeklyTarget`, under pairVerdict's hard rules, one practice a day, no repeat pair a week, fairness first (1/n weighting). Admin → Week plan reviews it (remove / move / hold / send, `adminWeekPlan`). Sending turns each pair into an ordinary `matchOffers` doc (`source: weekly_plan`, `planWeek`, `respondBy`), one `week_plan` push per person, and an honest `planStatus/{uid}` (owner-read). `appConfig/planner` switches — **`autoSend` (Sun 20:00) and `refill` (hourly 08–21, mid-week) are ON in production since 2026-10-06** (Polad: calls must get set up even when the admin is away; an auto-send pushes the admin `admin_plan_sent`). Plan offers give **48 h** to answer (`respondBy`), refill offers 6 h; whoever has not answered gets ONE `match_offer_reminder` halfway / at 12 h (`functions/offerReminders.js`, claimed in `reminded.{uid}`). A 20-learner emulator run of the whole week (`scratchpad/sim20.js`, `exports._sim` exists only under `FUNCTIONS_EMULATOR`) booked 80% of what eligible learners asked for. `requireCharter` limits planning to learners who accepted the charter.
- **Weekly roster** (2026-10-02, `functions/weekRoster.js`): only the people the admin ticks in Admin → Week → "Who practises" (`weekRoster/{monday}.uids`, admin-only rules) are planned (`loadPlannerInputs` — plan and refill), may join a practice block (`joinSlotTx` → 403 `not-in-roster`) or be matched at random (`canPair` without `direct`). **No list saved for a week → the most recent list of the last four weeks carries over** (`rosterOf`; the Sunday draft writes it down with `carriedFrom`, and Week/Matching say so); only when there has never been a list is it nobody — then the draft stores `noRoster` and pushes the admin `admin_roster_missing`. Dead accounts drop out through the planner's 21-day activity filter, not the list. Direct calls, admin proposals and teacher pairs are not gated.
- **Reliability** (Phase 5, `functions/reliability.js` pure + tested): over 28 days, only CONFIRMED practices — `no_show` +1, `late_cancel` +0.5, a booked `attended` −0.5; `partner_no_show`, `unmatched`, in-time cancels, unanswered proposals and direct calls never count. `watch` ≥ 1 point (admin only); `limited` ≥ 3 points or two no-shows in a row → the weekly plan gives ONE practice a week and never pairs them with a newcomer (`callCount` 0); two booked practices attended in a row lift it. `refreshReliability` runs at block close and on a late cancel and writes admin-only `reliability/{uid}`; the learner sees only `planStatus.limit` (reason + way back, never the points) on Today/Plan. Admin → Attendance shows the level and a Reset (`adminWeekPlan` `resetReliability`). At +10 min the one who came gets `partner_late` (it says "we're looking for another time" only when `refill` is on); the refill writes `replacement_not_found` when it finds nothing.
- **Favourite partners** (`users/{uid}/favorites/{peerId}`, owner-only, `src/utils/favorites.js`): a star on Partners or "I'd like to practise with them again" after a call. The planner adds +2 per star (mutual = +4) and skips the recent-partner penalty for a starred pair; it is a preference, never a promise, and the starred person is never told.
- **Online now** (2026-10-06, TEMPORARY — remove once the weekly plan carries everyone): `onlineNow` (us-central1) returns up to 12 learners seen in the last 150 s, filtered SERVER-side by the hard pairing rules (block / avoid either way, minor↔adult — the age band is private), never teachers/admin, never anyone with `users.showOnline === false` (Profile toggle). The strip (`OnlineNow.jsx`, `useOnlineNow` — every 60 s while visible) sits on Partners only (removed from Today 2026-10-06); Call = `navigate('/chat/<uid>', {state:{autoCall:true}})`, so `canPair({direct:true})` still decides. Switch: Admin → Matching «Online now list» = `appConfig/features.onlineNow` (missing = on).

Long-press / right-click: Copy, Edit (own text message, **15 min**, rules check `editedAt == request.time` and the window; the bubble says "edited"), Delete for me (localStorage `chatHidden:<chatId>`), Delete for everyone (blank + `deleted`). Report cards (`kind`) can be neither edited nor deleted. Pure helpers `src/utils/chatThread.js` (+ tests). Today shows the daily topic card right under the plan card; Online now is on Partners only.
- **Call topic** (2026-10-06): a call has ONE shared topic, `calls/{id}.callTopic` (`contentIndex`, `by`, `at`; missing = today's). The «Topic · Change» chip on the call screen opens `CallTopicPicker` (today, the coming days' topics with their date — `upcomingTopics` in `src/utils/topicQueue.js`, pure + tested, follows the session days the cycle advances on — then all topics); picking moves BOTH screens, the partner gets a one-line note, and the vocabulary sheet and every activity started afterwards pin that index. Today shows «Next topics» under the topic card (tap = that topic's sheet). A MISSING `calls` doc is readable by the two uids its id names — otherwise the call screen's listener died before the first call between a pair existed and the caller hung on «Calling…».
- **Missed call**: `reconcileCallStats` sees `calling → ended` with no answer and pushes `missed_call` to the person called (claimed once in `slotRuns`); on web and Android it replaces the ringing notification (same tag). A decline goes through `rejected` and is not reported.
- **Admin pair proposals** (`matchOffers`, `adminProposeMatch` / `respondMatchOffer` / `adminCancelOffer`): a proposal is NOT a booking — only the second yes books it, through `bookPairTx` (the same core `teacherSetMatch` uses, so reminders/no-show/cancel keep working). Proposals use the 2-hour Baku slot blocks. One pending proposal per person **per 2-hour block**; a proposal with `respondBy` closes at that time (silence is never held against anyone). Who declined and why lives in admin-only `matchOfferNotes`; the other person is only told "this time did not work out", and only if they had already accepted.
- **Individual lessons** (2026-10-02; replaced the group-class model, which had no real classes): a teacher's linked student (`users.teacherId`, teacher code) gets an enrolment `tutorStudents/{uid}` (level A2/B1, `packageSize`, platform Preply/Meet, link) and their OWN lessons `tutorLessons/{id}`, each stored with its own `at` — moved, cancelled (`cancelledBy`), restored or removed one by one. The admin adds a learner without the code (teacher dashboard → "Add a student" → their page → Start lessons): `teacherLesson` "start" by the admin links an unlinked learner to the admin (`users.teacherId`, roster row, counters — `addToTeacherRosterTx`, shared with `claimTeacherCode`); other teachers still need the code or an accepted invite (the learner's consent). Today shows the next lesson within 48 h as its own picture card ("Lesson 2 · Tomorrow…", purple frame) above the daily card, which reads "Today's practice topic" — a lesson's topic is fixed when planned, the daily one keeps moving. Every write goes through `teacherLesson` (the student's teacher or the admin; `functions/tutorLessons.js` pure + tested: weekly pattern → dates in Baku time, next-topic suggestion, held numbering). Only HELD lessons use the package; held lessons are numbered by date (`n` = the story episode). Starting lessons / a bigger package extends `freeAccessUntil` by 90 days — only for the admin or a `teacherVerified` teacher, because `role: teacher` is self-chosen at sign-up. Marking held builds `homework/{lessonId}` (topic words + dictation + a personal half from the learner's analyses since the previous held lesson, `functions/homeworkBuilder.js`); undo hides, never deletes. The learner's planned lessons sit in Today's "Coming up" and the Plan tab's schedule next to booked practices (`useMyLessons`, `lessonItems`/`mergeSchedule`, `LessonRow` — a book icon and a purple bar; tap → materials), `LessonsCard` keeps package progress + homework, and the learner prepares on `/class/:lessonId` (the topic sheet, `DailyTopicModal topicIndex`); the teacher sees `StudentLessons` on the student page and "This week" on the dashboard. A teacher's `tutorLessons` query must include `teacherId == me` or the rules refuse it. `practiceSlotTick` pushes each planned lesson twice — `lesson_prepare` ~3 h before and `lesson_soon` 15 min before, both opening `/class/:id` (`tutorLessons.reminderDue`; the lesson's `reminded.{prepare,soon}` holds the start time it was sent for, so a moved lesson is reminded again; paused enrolments get nothing; index `tutorLessons (status, at)`). Before a lesson the teacher opens the student's brief (`teacherStudentBrief` → `classBrief.buildStudentBrief`: their mistakes and words since the last held lesson, that lesson's homework progress — counted, never guessed). `homeworkStepKeys` (`src/utils/tutorLessons.js`) is mirrored in `functions/classBrief.js` — change both. The Julian story (`functions/storyBible.js`, approved by Polad) is ONE shared episode per level: `storyChapters/{level}_{n}`, written by `teacherStory` (DeepSeek + Deepgram audio in Storage, agreeing with the level's earlier episodes; no lesson topic) and approved once — only by the admin or a `teacherVerified` teacher, since every student of the level reads it. Episode n is read BEFORE the student's n-th lesson on `/class/:lessonId` (listening reveals the last choice, reading ends on the dilemma the lesson debates); its recorded sentences become the homework dictation. Learners read approved episodes only if they have a `tutorStudents` doc. Import `cohort.css` before `story.css`, and `ui.css` before `plan.css`, or the CI build fails on CSS chunk order.
- **Lessons** (`/lessons`, `/lessons/:lessonId`): 17 short lessons in 4 modules (`src/data/lessons.js`) teaching HOW to practise — describing, keeping a call alive, Taboo, debate. Written because the median production call ran 40 s and two thirds opened no activity. **Nothing is locked**: `nextLesson()` (`src/utils/lessonMap.js`, pure + tested) only RECOMMENDS. Progress is the one client-written progress doc, `lessonProgress/{uid}` — safe only because nothing is granted by it; if a lesson ever unlocks anything, move the write to a Cloud Function. Lesson **ids are storage keys** — add, never rename. Phrase meanings (az/tr) live in the lesson data and are revealed on tap, like `KeywordChips`.
- **Topic cycle**: global monotonic tick in `appConfig/cycle`; `topicIndex = cycleTick % TOPIC_COUNT`. Progress is **not** stored per user — the client computes `currentCycleTick - startTick`. `functions/dailyQuestions.json` and `src/data/weeklyContent.js` must stay the same length.
- **Session schedule**: `src/utils/sessionSchedule.js` + `appConfig/session`. Times are **Baku (UTC+4, no DST)** so every client computes the same window. **One session only: 21:00** (the 16:00 afternoon session was removed — never re-add a daytime reminder). 21:00 is a **recommended hour shown every day**; `sessionDays` Mon/Wed/Fri + `bonusDays` Sun only mark the **main** days (crowd + topic-cycle advance), they never gate practice — any user can search for a partner at any time. Weekdays are **0=Sunday…6=Saturday — Sunday is 0, not 7**. Use `getUpcomingSessionWindow()` (countdown) / `getSessionWindow()` / `getNextSessionDay()` — don't hand-roll time math. The Firestore doc's `sessions` array **overrides** the code defaults, so a config change needs both.
- **Call minutes are authoritative from call timestamps**, never the client stopwatch. A call starts at `connectedAt` (written once when both are in the Agora channel) → `matchedAt` → `createdAt`. The client's `authoritativeDurationSec` is only a claim: the server credits `trustedCallSeconds` (functions/practiceStats.js) = min(claim, endedAt − start, 60 min), and the rules only accept `serverTimestamp()` for a call's clock fields. Call ids are per PAIR (`call_<a>_<b>`), so server code creating a call must overwrite the doc, never merge — a merge inherits the previous call's flags and duration.
- **Firestore rules end in a catch-all deny** — a new collection without an explicit `match` is fully blocked.
- **Push payloads differ by platform** (`functions/pushTokens.js`): web = data-only + `Urgency: high` (the SW displays it); Android = `notification` block + `priority: high`. Adding a notification block to web causes duplicate notifications.

- **Admin panel** (`src/pages/Admin.js` + `Admin.css`): compact sticky header + tabs Students (with the Packages switch and a per-learner package menu) · Applicants · **Matching** (`AdminMatching.jsx`, pure helpers `src/utils/matching.js`: everyone's week — planned vs target, free time as a 7×8 grid of Baku blocks, late joiners marked new and added to the week's list in one tap — beside the week's real pairs, open proposals + bookings; "Change" swaps one side by withdrawing the offer / `cancelSlotMatch` and proposing the new pair, ticking two people proposes a fitting block; wide layout on a computer) · Week (`?tab=plan` still works) · Sessions · Attendance · Intros (the old Cohorts tab is hidden since 2026-10-03; `AdminCohorts.jsx` is kept). Live admin lists must not reorder under the admin's finger — use `stableOrder` (`src/utils/stableOrder.js`): a row keeps the place it got when it appeared until the filters change. Panels that grow with a selection go in a bar pinned to the bottom (`aa-sticky-bar`), never above the list.
- **Topic sheet on a computer** (≥900px landscape, App.css wide block): videos AND pictures (`PictureDescribing`, `.pd-*`) share one layout — media left, words/starters/questions right, ‹ n / N › below, ← → keys. Phones keep the one-column view.
- **Describe-video clips in the Android app**: only `licensed: true` clips (Pexels / CC0) — three per topic (`licensedVideosForTopic`); `scripts/strip-native-videos.js` keeps only their files in the APK/AAB and fails the build if it finds none. ## Conventions
- HTTP functions: `setCors(res, ...)` on every path, 204 short-circuit for `OPTIONS`, `verifyAuth(req)` for auth, and **`enforceRateLimit(...)` on every AI/paid endpoint**.
- **UI copy is English.** The whole interface was moved to English and `i18next` removed (2026-08-21). The ONE exception is the analysis report, which stays in the learner L1 (`users.preferredLanguage`, az/tr) — see `src/utils/feedbackLanguage.js`. `public/index.html` is `lang="en"`; do not set it back to `az` without also reverting the copy, or `text-transform: uppercase` breaks Azerbaijani text.
- Use the design tokens in `src/index.css` (spacing `--s-*`, radius `--r-*`, type `--fs-*`, z `--z-*`) and the primitives in `src/components/ui/` — no raw px, no raw colours.
- **Palette: Plum — ONE purple family.** `--peer`/`--accent` (deep purple) = a real person, `--ai` (lighter purple) = AInur; the five in-call activities are further steps of the same band. **No green, amber, teal or cyan anywhere.** Two exceptions: red (`--danger-solid` + `--ink-on-danger`) for destructive controls and wrong answers, and **coral** (`--coral` / `--coral-soft` / `--coral-ink`, added 2026-10-01) which means *progress* only — Lab charts, the score ring, a "+29" change chip, the Lab tab underline. `--coral` is a graphic colour (≥3:1), never text; text goes `--coral-ink` on `--coral-soft`. People and buttons stay purple. There is no `data-palette` switch — it was removed with the recolour. Nothing glows: `--glass-lift` is the only shadow a surface gets, and there is no page-wide radial background.
- **`--ai` vs `--ai-fill`:** `--ai` is for text, icons and borders; a FILLED AInur control takes `--ai-fill` with `--text-on-ai`. Using `--ai` as a fill fails contrast in light mode.
- Small `--text-secondary`/`--text-muted` text at 11–13px is `font-weight: 600`; bottom-nav labels are 700.
- UI icons come from `lucide-react`, never emoji. Emoji are fine in CONTENT (a topic label), never as an icon.
- Match surrounding code style; the codebase uses explanatory comments for non-obvious decisions — keep that habit.
- Tests cover pure helpers only: `CI=true npx react-scripts test --watchAll=false` (web) and `node --test` in `functions/`. Behaviour is still verified by running the app (see the `verify` skill). The dev build talks to **production** Firebase; admin-only flows are verified on local emulators (`firebase.emu.json`, `scripts/emu-functions-server.js`, `REACT_APP_USE_EMULATORS` — see the `verify` skill).
